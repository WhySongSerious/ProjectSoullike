# 역할 분담과 스크럼 계획

기준일: 2026-09-22 / 제안 완료일: 2026-11-06 / 시간대: Asia/Seoul.
사용자가 확정한 것은 3명 구성·역할 방향·11월 초 개발·스크럼 운영입니다. 정확한 종료일, 주간 가용시간, SP는 첫 계획 회의에서 확정할 제안값입니다.

## 목표

보스 1종·전투 공간 1개에서 시작→교전→승리 또는 사망→재시작을 끝까지 플레이할 수 있는 데모. 기존 이동·카메라·콤보·락온·골렘 상태 머신을 확장합니다. 전체 게임/추가 스테이지 제작은 이번 최소 목표에 포함하지 않습니다.

## 책임과 협업

| 팀원 | 제품·팀 책임 | 구현/산출물 책임 | 리뷰 협업 |
| --- | --- | --- | --- |
| 송재혁 | 팀장, 우선순위·범위 결정, 스크럼 진행, 통합 | 플레이어·입력·전투 루프·VFX·애니메이션·빌드 | 지민과 코드 상호 리뷰, 다윤과 연출 검수 |
| 천지민 | 보스 기술 책임, 기술 위험·막힘 공유 | 보스 AI·패턴·판정·NavMesh·전투 예외/안정화 | 재혁 코드 리뷰, 다윤 패턴 수치 협의 |
| 이다윤 | 기획·아트 방향, 수용 기준·테스트 정리 | 패턴/밸런스 표·UI/리소스·플레이테스트·시연 문서 | 개발자와 구현/가독성 검수 |

3인 팀이므로 별도의 관리 전담자를 두지 않습니다. 재혁은 제품 우선순위 결정과 스크럼 진행을 겸하고, 다윤은 기획 수용 기준을 준비합니다. 매 스프린트의 실제 수행량은 세 명이 함께 정합니다.

재혁의 관리·통합·VFX 과부하를 막기 위해 주간 가용시간의 약 60~70%만 기능 작업으로 계획하고 나머지를 리뷰·통합·버그 대응에 남깁니다. 다윤에게 코딩 역량을 가정하지 않습니다. UI 코드 연결은 재혁, 보스 모션 연결은 지민이 맡고 다윤은 리소스와 적용 기준을 제공합니다.

S0와 S6는 준비/마감 구간이고 S1~S5는 1주 스프린트입니다. 팀 일정상 휴일·시험·취업 일정으로 가용시간이 줄면 선택 기능과 미착수 작업을 먼저 줄입니다.

S4의 재혁 빌드 작업에 지민은 전투 회귀/성능 원인 분석, 다윤은 테스트 실행/시연 동선 검수로 참여합니다. 자기 이슈가 먼저 끝나면 새 기능을 벌리기보다 현재 스프린트 목표의 리뷰·테스트를 지원합니다.

## 회의와 기록

- 주초 계획 30분: 스프린트 목표 1개, 개인 가용시간, Ready 작업, 예상 검증 방법 합의.
- 매일 10분 이내: 완료한 것/오늘 할 것/막힘을 이슈 진행 기록으로 공유. 필요할 때만 짧게 모입니다.
- 주중 백로그 정리 15분: 다음 작업의 요구사항·의존성·추정 정리.
- 주말 리뷰 20분: 문서 설명보다 실제 실행/산출물을 보여주고 수용 기준 확인.
- 회고 10분: 잘된 점 1개, 막힌 점 1개, 다음 주 변경 1개를 팀 허브에 기록.
- 막힘은 발생 당일 공개. 하루 넘게 풀리지 않으면 팀장이 함께 해결하거나 범위를 축소.

## 추정·상태·완료

SP 1/2/3/5는 상대 난이도 초안이며 시간·개인 평가 점수가 아닙니다. 첫 주 실적과 가용시간으로 다시 추정합니다. 5SP 작업은 착수 전에 1~2일 단위 하위 작업으로 나눕니다. 개인 동시 진행은 1개를 기본으로 합니다.

상태: Backlog → Ready → In progress → Review → Done. 막힘은 상태와 별도로 Blocked로 표시하고 원인·도움 요청·재확인일을 적습니다. 제목의 S번호는 목표 스프린트이며 실제 상태를 의미하지 않습니다.

**Ready:** 담당·완료 기준·선행 작업·리뷰어·검증 방법이 정해짐.
**Done:** 완료 기준 충족 + 검증 증거 + 동료 검토 + 문서 반영 + 해당 PR 병합/산출물 반영. 코드 작성만으로 완료 처리하지 않습니다.

C# 런타임 변경은 `dotnet build Assembly-CSharp.csproj`, 에디터 변경은 Editor 프로젝트도 빌드합니다. 동작 변경은 Unity Console·Play Mode·관련 씬을 확인합니다. 문서만 변경하면 `git diff --check`를 사용합니다.

## 범위 변경과 선택 기능

회피·전투 루프·보스·핵심 연출·안정화가 먼저입니다. 가드/패링/적응형 난이도와 QR 컨트롤러는 선택 백로그입니다.

QR 컨트롤러는 **가능하면 진행**합니다. S3 리뷰에서 1차 검토하고, S4 전반에 핵심 루프 검증·차단 오류 해결·충분한 여유가 확인되면 담당자와 작은 구현 범위를 정합니다. 10/26 기능 동결 전에 검증할 수 없는 범위는 후속 개발로 이월합니다. 전투 품질과 납품 일정은 줄이지 않습니다.

새 요구사항을 추가하면 같은 크기의 미착수 작업을 빼거나 후순위로 내립니다. 일정이 밀리면 새 보스/스테이지·추가 아트·선택 기능을 먼저 줄이고 재시작/안정화/검증은 유지합니다.
